# Project 2: isolated repair-case screen

## Plain-language result

The cluster can run a small repair test inside a no-network Bubblewrap sandbox on a CPU compute node. **Two of the three proposed PySnooper cases are usable** under their specified Python 3.8.1 interpreter: buggy code fails the targeted test and fixed code passes. Case 1 passes on both and is excluded. No coding agent, generated patch, retrieval comparison, or ML experiment was run, so this is harness validation rather than an agent result.

| BugsInPy PySnooper case | Buggy test | Fixed test | Screen decision |
| --- | --- | --- | --- |
| 1, Chinese output | pass | pass | Exclude: no reproduced failure on this Linux setup. |
| 2, custom representation | fail: `TypeError` on `custom_repr` | pass | Usable development case. |
| 3, file output | fail: `NameError` for `output_path` | pass | Usable development case. |

The [exit-code table](implementation/repair_case_screen_2026-09-28.tsv) and [six corrected-run logs](implementation/repair_case_screen_logs_2026-09-28) are saved locally. The corrected screen was Slurm job **21724564**, exit code 0, five seconds wall time. Cases 2 and 3 each ran in about a second per revision. Case 1 and 2 share the same buggy commit, so even if case 1 had failed they would not be independent repository examples.

## What was checked

The [source preparation script](implementation/prepare_pysnooper_cases.py) uses the pinned public [BugsInPy](https://github.com/soarsmu/BugsInPy) metadata and [PySnooper](https://github.com/cool-RR/PySnooper) commits. It puts each buggy implementation and fixed implementation in separate trees. The candidate tree gets the **test tree from the fixed revision**, including local test helpers; the implementation stays byte-identical to the buggy commit. This is an explicit extension of BugsInPy's checkout behavior, which transfers the named test file but did not supply the extra local test helpers needed by case 2. The preparation check rejects a changed buggy implementation, `.git` history, or `bug_patch.txt` in a candidate tree. The evaluator tree is outside the mounted candidate sandbox.

The [sandbox probe](implementation/repair_sandbox_probe.py) ran as Slurm job **21724367** on a CPU node and verified that `/home` and `/root` were absent, source was read-only, network access failed, and temporary scratch was writable. The [probe job](implementation/run_repair_sandbox_smoke.sbatch) and [case-screen job](implementation/run_repair_case_screen.sbatch) used unprivileged Bubblewrap namespaces. Test jobs also cleared environment variables, mounted only the specific source tree and Python environment, and used a 45-second per-test timeout. These checks support this narrow runner configuration; they do not constitute a general security certification.

The cluster's Podman remains a poor default for this work: it has no cached image and reports missing subordinate UID/GID ranges plus a network-backed image store. A separate Python **3.8.1** environment was created by capped CPU job **21724399**. Test dependencies were downloaded as wheels, then installed with network disabled by [job script](implementation/run_repair_wheel_install.sbatch). The environment occupies about **409 MB**, with roughly 3 MB of wheels and 3 MB of candidate trees on the remote filesystem. No GPU time was used. Personal storage quota is still unverified.

## Remaining gate

The original proposed three-case pilot cannot use case 1. A replacement from another repository would improve diversity but requires its own fixed test, dependencies, exact interpreter, and fail/pass screen. A two-case development smoke can exercise the agent loop, yet cannot support a credible retrieval-effect claim. Before an autonomous repair comparison, freeze the replacement or explicitly choose a two-case smoke, model and tool budget, candidate patch permissions, regression tests, timeout, and success metric. Keep the fixed trees and answer patches outside every agent-accessible mount. The [original benchmark proposal](AGENT_BENCHMARK_DECISION_2026-09-27.md) remains the broader design reference.

**Replacement preparation and runtime boundary:** BugsInPy tqdm case 3 requests Python 3.6.9 and `tqdm/tests/tests_tqdm.py::test_bool`. The pinned commits and test tree are present. [Preparation code](implementation/prepare_tqdm_case.py) verified 12 candidate implementation Python files against the buggy commit, copied six fixed-revision test files, and excluded Git history and answer patches. After SSH access returned, a capped Python 3.6.9 conda setup job (**21726087**, 2 CPU, 2 GB, 15 minutes) timed out while verifying its package transaction. An offline retry from the cached packages (**21726285**, 2 CPU, 2 GB, 12 minutes) timed out at the same stage. Their dependent wheel-install and test jobs were canceled by Slurm without running. The incomplete interpreter directories were preserved separately; neither is usable. This is an environment-setup failure, **not** a case fail/pass result.

A separate, explicitly **modified-runtime exploratory screen** reused the established Python 3.8.1 environment with pytest 6.2.5 and the pure-Python nose 1.3.7 wheel mounted read-only. [Job 21726332](implementation/tqdm_py381_screen_results_2026-09-28.tsv) completed in four seconds inside the same no-network Bubblewrap test boundary: buggy `test_bool` failed with `TypeError: 'NoneType' object cannot be interpreted as an integer` for an empty generator, and fixed `test_bool` passed. The [two logs](implementation/tqdm_py381_screen_logs_2026-09-28) show a real behavioral difference, not an import/setup failure. This can support a **clearly labeled modified three-case development harness** with one case from another repository. It does not reproduce BugsInPy's specified Python 3.6.9 task, and no repair agent has run on it.

**Regression baseline:** CPU job **21726345** ran each fixed revision's main test file under the no-network Python 3.8.1 sandbox. [Results](implementation/repair_regression_results_2026-09-28.tsv) and [logs](implementation/repair_regression_logs_2026-09-28) show 31 PySnooper case-2 tests passed, five PySnooper case-3 tests passed, and 55 tqdm tests passed with one skipped. Each file finished in roughly one second, below its 120-second cap. These are proposed regression commands for a later patch evaluator; the agent comparison and any generated patch remain unrun.
