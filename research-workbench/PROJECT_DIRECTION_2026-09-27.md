## 1. Replace the small Sherlock corpus with a substantial biomedical-literature task

**Mission.** Turn the two-stage LLM course work (domain continued pretraining followed by supervised fine-tuning) into evidence-grounded *research-literature* question answering. The assistant should answer from a supplied article and identify when the article does not support an answer. This is about reading papers, not clinical decision support.

**Corpus chosen.** Use English cardiovascular/electrophysiology articles from the [PMC Open Access Subset](https://pmc.ncbi.nlm.nih.gov/tools/textmining/), restricted initially to CC0 or CC BY article versions. PMC says the overall subset contains millions of full-text articles, but it does **not** establish the number passing these topic, license, language, date, and quality filters. The working *target* is up to 100,000 eligible articles, with the actual count and token volume established by a metadata inventory before download or training. Include title, DOI/PMCID, publication date, article type, license, section headings, and source version in the manifest. Use PMC's [Cloud Service or OAI-PMH service](https://pmc.ncbi.nlm.nih.gov/tools/oai/) for systematic retrieval; the legacy OA API was [retired in August 2026](https://pmc.ncbi.nlm.nih.gov/tools/oa-service/). Do not bulk scrape the PMC website.

**Quality controls.** Remove retractions, corrections, duplicates, nonresearch items, missing or ambiguous licenses, and articles with broken XML. Keep the license and citation attached to every document. Make document/DOI-disjoint train, validation, and test partitions, with a later publication-date test. Run near-duplicate detection. Exclude every PubMedQA evaluation PMID/PMCID and close text matches from the training corpus to avoid benchmark contamination. A small expert-reviewed sample should audit whether extraction preserves methods, results, and conclusions. The exact sample size and acceptance threshold need agreement before this analytic branch runs.

**Models and comparison.** Reproduce the old Qwen2.5-3B QLoRA/SFT baseline first, then compare base model, domain-adapted model, and domain-adapted plus response-only SFT under the same input/evaluation. A larger candidate is the official Apache-2.0 [Qwen3-8B-Base](https://huggingface.co/Qwen/Qwen3-8B-Base), subject to a measured memory/time budget; it should not replace the 3B control until a clean baseline exists. [PubMedQA](https://pubmedqa.github.io/) offers 1,000 expert-labeled yes/no/maybe instances, 61,200 unlabeled, and 211,300 artificial QA instances; use its official split and [evaluation code](https://github.com/pubmedqa/pubmedqa) as one external benchmark. Keep its expert test set out of SFT. Add a small citation/abstention set drawn only from licensed articles and evaluated for supported claims, because PubMedQA alone does not test citation quality or abstention. Artificial QA labels need a noise audit before use as training targets. Report accuracy and macro F1 for PubMedQA plus evidence support and abstention for the new set; do not claim clinical correctness.

**Scale and alternatives.** The 100,000-article ceiling is a planning cap, not a commitment to train on every full text. First inspect the inventory and token count; then choose a fixed token budget that fits the measured GPU/storage allowance. A 10,000-article pilot and the old Qwen 3B adapter are cheaper alternatives. This corpus is large enough to be meaningful while retaining provenance and compatible licensing. If the inventory exposes too few eligible cardiovascular papers, broaden to all biomedical CC0/CC BY research articles and keep cardiovascular articles as a separate evaluation slice.

## 2. Build a repository repair and ML experiment agent

**Mission.** One agent has two measured modes: (a) retrieve relevant repository code, documentation, and tests, propose a patch, run tests in an isolated environment, and report whether the issue was resolved; (b) run bounded, reproducible ML experiments and promote only changes that improve a frozen validation metric. A working repository repair agent is a software engineering project; the experiment mode is an ML research workflow. Retrieval must be implemented and measured before any RAG or RAGAS claim.

**What comes from Karpathy.** The [original `autoresearch`](https://github.com/karpathy/autoresearch) separates fixed preparation/evaluation (`prepare.py`), the sole mutable training file (`train.py`), and human-authored instructions (`program.md`). It fixes each training run at five minutes and compares validation bits per byte on one GPU. The published baseline was tested on an H100; its sample log reports about 45 GB peak GPU memory. Copying that baseline unchanged to a 24 GB RTX 3090 would be an unverified and likely infeasible run. Adapt the *experimental contract* to the cluster's measured hardware and to a small chosen training task. The upstream README itself recommends reducing model/data settings for smaller devices. Record the upstream commit and license if any code is reused.

A shallow reference checkout on 27 September 2026 pins upstream `master` at `228791fb499afffb54b46200aca536f79142f117` (MIT license). Its `program.md` confirms the fixed evaluator, one editable `train.py`, five-minute training metric, and result log. The new ledger and retrieval scripts here are original implementation of that contract; no upstream training code has been copied. The upstream open-ended loop and reset instructions are not part of the bounded project plan.

**Own contribution to test.** Add *retrieval-grounded experiment memory*: the agent searches indexed repository docs, prior hypotheses, patches, metrics, and failure logs before proposing its next change. Compare this with an otherwise identical agent that has no retrieval. For both modes, store candidate diff, source evidence, environment, data hash, budget, measured metric, failure reason, and final disposition. The search index may use only training/validation history; sealed test answers must not be retrievable by the agent. This is a proposed innovation, not yet a proven improvement.

**Evaluation.** Begin repair mode with a small, frozen set of real Python issues with executable tests; later consider the official [SWE-bench harness](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/evaluation.md), which checks patches inside Docker. A full SWE-bench evaluation needs substantial Docker storage (its [setup guide](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/docker_setup.md) recommends at least 120 GB), so it is not the first run. Measure task resolution, test regressions, token/tool cost, and retrieval contribution. In experiment mode, freeze dataset split, preprocessing, metric, maximum runtime, and evaluation code before agents edit `train.py`. Run a baseline, bounded candidate runs, then repeated confirmation of a winner on the same protocol. A held-out test is used only after selection. The first ML task can be a compact ECG or text baseline from projects 3 or 1; choose it after the hardware inventory. The repair and experiment modes share records and retrieval but have different success metrics.

The local Mac currently has about 16 GiB free and the installed Docker CLI has no running daemon (read-only checks on 27 September 2026). The official SWE-bench storage recommendation is therefore not met locally. [BugsInPy](https://github.com/soarsmu/BugsInPy) is a candidate real-Python-issue pilot with per-bug tests, but its exact cases, dependencies, and container size must be vetted before choosing a frozen task set. No repair benchmark has run yet.

**Execution boundary.** Edit candidates only in isolated worktrees/containers; execute generated code without cluster credentials or access to unrelated files. Never reset a user checkout to discard an experiment. No open-ended overnight loop or automatic cluster submission. Set an explicit run count and GPU-hour ceiling for each approved batch.

## 3. Rebuild ECG as a patient-generalization study

**Current starting point.** The old team notebook uses Kaggle's 187-sample MIT-BIH heartbeat CSVs and has a saved 1D CNN result of 0.9802 accuracy and 0.8967 macro F1 on a beat-level test. It cannot demonstrate patient-disjoint evaluation because the CSVs in this copy lack patient IDs. It also runs SMOTE before one validation split in part of the notebook, so that path's validation score may include synthetic-neighbor contamination; the effect on any particular saved result requires tracing its exact cell path. The project is deep learning on a 1D physiological signal, not computer vision.

**Paper lineage.** The [Kaggle source](https://www.kaggle.com/datasets/shayanfazeli/heartbeat) attributes the processed dataset to Kachuee et al., [*ECG Heartbeat Classification: A Deep Transferable Representation*](https://arxiv.org/abs/1805.00794). The course presentation describes a CNN/attention/transformer hybrid resembling [CAT-Net (2024)](https://www.sciencedirect.com/science/article/pii/S1746809424002696), but the inspected notebook and presentation do not explicitly cite CAT-Net. Treat it as an architectural comparison, not proven derivation. A separate paper brief checks later direct comparisons and their methods.

**Data and evaluation.** Recreate beats from raw [MIT-BIH](https://physionet.org/content/mitdb/1.0.0/) records with record/subject IDs and a locked patient-separated split. MIT-BIH has 48 half-hour recordings from 47 subjects and roughly 110,000 beat annotations. Keep preprocessing and any resampling entirely inside training folds. Add [INCART](https://physionet.org/content/incartdb/1.0.0/) as an external test after lead, sampling-rate, annotation, and class mapping are explicitly reconciled; it has 75 half-hour recordings from 32 source Holters and over 175,000 beat annotations. Cross-dataset evaluation must report which classes remain comparable. Do not simply pool [PTB-XL](https://physionet.org/content/ptb-xl/1.0.2/) into beat-level labels; it has a different record-level multilabel task.

**Raw-data status (27 September 2026).** The complete MIT-BIH signal/header/annotation set is downloaded and checksum-verified. The [record inventory](implementation/mitdb_record_inventory.json) confirms 48 records, 47 subject groups, and 112,647 annotation events, including non-beat symbols. No patient split, five-class remapping, beat extraction, or model run has been done. The [implementation README](implementation/README.md) gives the acquisition and environment details. PhysioNet lists INCART as 563.5 MB compressed; it remains a later external validation source.

**Data-build update, 28 September:** The approved [raw ECG build](ECG_DATA_BUILD_2026-09-28.md) produced 109,438 extracted one-second beat windows, class mappings, and two validated subject-disjoint split candidates. The primary 44-record four-class study has 100,667 usable windows. INCART is still a later external test.

**Baseline result, 28 September:** One approved RTX 3090 CNN job completed on candidate A. [The result report](ECG_BASELINE_RESULT_2026-09-28.md) records 94.10% accuracy but only 0.4521 macro F1, with 1/429 S and 0/384 F beats detected. That test result has now been inspected and must not be treated as an untouched final benchmark for subsequent model choices.

The [next bounded ECG comparison proposal](ECG_NEXT_COMPARISON_PROPOSAL_2026-09-28.md) fixes an unweighted control, a moderately class-weighted single-beat model, and a weighted past-context model for a single capped development job. It needs separate approval and an external fresh test before any stronger generalization claim.

**Split caveat.** The commonly reused 44-record DS1/DS2 assignment places record 201 in DS1 and 202 in DS2 ([published record lists](https://www.mdpi.com/2079-9292/9/11/1790), Table 2), while the [MIT-BIH directory](https://physionet.org/physiobank/database/html/mitdbdir/intro.htm) identifies them as the same person. That assignment is therefore record-disjoint but not strictly subject-disjoint. Our primary evaluation must keep both in one partition, and any score on the historical assignment must carry this caveat. The 44-record convention also excludes four paced recordings (102, 104, 107, 217); choosing whether to match that scope is a method decision, not an automatic preprocessing step.

The [original ECG protocol brief](ECG_PROTOCOL_DECISION_2026-09-27.md) explains why the four-class primary study and separate five-class comparison were chosen; the [data-build report](ECG_DATA_BUILD_2026-09-28.md) records the implemented extraction, candidate splits, rare-class counts, and remaining training gate.

**Models and own contribution.** Reproduce a compact 1D CNN under the new split, then compare a CAT-Net-style local/global model and a smaller hierarchical-attention alternative. The main new question is whether *short rhythm context around a target beat* improves rare-class detection for unseen patients without compromising calibration or inference cost. Compare single-beat versus multi-beat context with identical patient splits and class mapping. Add calibrated abstention for low-confidence and out-of-distribution recordings as a separate, measurable extension if the initial comparison supports it. Report macro F1, per-class precision/recall, patient-level variation, calibration, and cross-dataset performance; accuracy alone is inadequate. A UI can illustrate the eventual model, but is not the research result.
