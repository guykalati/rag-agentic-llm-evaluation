# Candidate 1, frozen before scoring

The baseline reached training loss about 0.82 nats at the five-minute limit and independently scored 1.203280 validation bits per byte. Hypothesis: a cosine decrease from the same initial AdamW learning rate `3e-4` to 10% of it by the end of the fixed 300-second window will improve final validation prediction by reducing late noisy updates. The only candidate change is to the learning-rate value in `train.py`; the dataset, model, batch size, seed, optimizer type, train duration, validation calculation, and checkpoint interface remain fixed. Candidate source SHA-256: `8988aa34384fc685a4182b168933a70f0567f0bd1863717f09a807ebe2f56f5e`.

One RTX 3090 run uses at most five training minutes plus startup and verification within a 10-minute Slurm cap. This is the final training slot in the first batch because a failed pre-score baseline already spent five GPU minutes. The candidate is a development success only if the independently recomputed `val_bpb` is below 1.203280; one seed cannot establish a reliable improvement. No validation thresholds, source examples, or data splits are changed after scoring. A cheaper alternative was to stop at the verified baseline, but one bounded candidate tests that the edit/run/keep-or-discard workflow works end to end.
