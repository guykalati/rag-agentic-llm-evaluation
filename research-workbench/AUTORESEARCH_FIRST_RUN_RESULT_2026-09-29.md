# Project 2: first bounded autoresearch-style experiment result

## What works now

The first real experiment-mode task now follows the essential [autoresearch contract](https://github.com/karpathy/autoresearch): fixed data preparation and validation code, a single editable training file, a human-authored `program.md`, five-minute GPU training per candidate, and a metric ledger. The task is next-byte prediction on the public [TinyStories GPT-4 clean dataset](https://huggingface.co/datasets/karpathy/tinystories-gpt4-clean). This is a small engineering task for the university RTX 3090, not Project 1's cardiovascular literature mission or a competitive language-model result.

The frozen dataset revision is `0397e27157956705a0260709da3095bb9c43d6a7`. CPU preparation job **21731956** scanned 177,770 stories and saved **134,217,966 training bytes** and **2,097,193 validation bytes** after exact-story deduplication and deterministic story-level hash splitting. It found no duplicate story text in that prefix. The validation scorer evaluates **2,097,152** next-byte targets in nonoverlapping 256-byte contexts. Source, split rule, byte counts, and SHA-256 hashes are in the [data manifest](implementation/autoresearch_tinystories/data_manifest_2026-09-29.json). No held-out test was used.

The first baseline attempt, job **21731969**, completed five minutes of training but failed before validation due to an overly strict `cuda` versus `cuda:0` device comparison. It produced no checkpoint. The device check was corrected without changing the scoring formula or data, a GPU preflight was added, and the baseline was rerun. That failed allocation counts toward the batch's **15 training GPU-minute** ceiling. CPU preparation took 50 seconds. A separate GPU Bubblewrap probe, job **21732605**, confirmed CUDA worked inside a no-network mount namespace without the cluster home directory. The candidate runner then independently checked the immutable file hashes, mounted only `prepare.py`, `verify.py`, `train.py`, and the read-only data into the sandbox, and provided one writable output directory.

## Interpretation and next research gate

This establishes a reproducible edit → fixed-time train → independently score → retain/reject loop on the cluster. The baseline remains selected, and the [experiment ledger](implementation/autoresearch_tinystories/experiment_2026-09-29.json) shows **zero remaining runs** in this first batch. The cosine result is one failed hypothesis, not a general statement that learning-rate schedules are harmful. The baseline has only one seed; there has been no repeated confirmation, sealed test, autonomous multi-candidate search, or measured advantage from the proposed development-history retrieval. Future work should first confirm baseline variability on agreed seeds, then predefine a larger task and a matched memory-on/off agent comparison. Any new training batch needs its own fixed run count and budget; the old ledger must not be reopened or extended post hoc.
