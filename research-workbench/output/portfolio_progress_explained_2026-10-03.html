What does this project do?

A user asks a question about an article. The model reads supplied article text, answers the question, and copies the passage that supports its answer.

Later, domain adaptation may help the model understand biomedical writing. We must test that benefit against the unchanged base model.

Problem A: a large search result is not a usable corpus

A corpus is a collection of text used for training or evaluation. The first broad search returned 201,510 candidate records.

Many records mention heart disease only in the introduction. Others describe animals, cells, reviews, protocols, or unrelated topics. We cannot treat all search matches as human cardiac research.

We downloaded source XML, extracted text, and recorded identifiers and checksums. A checksum is a fingerprint used to detect changed files.

Problem B: licensing, retractions, and evaluation overlap need separate checks

  • Licensing: use the selected CC BY / CC0 policies. Keep each source's license record.
  • Benchmark overlap: exclude all 1,000 expert PubMedQA question PMIDs. Screen text overlap with the frozen benchmark contexts.
  • Duplicates: compare exact identifiers and extracted bodies. Similar-text checks do not prove the absence of paraphrases.
  • Notices: distinguish a retraction notice, its target paper, and a correction. A correction needs review; it does not automatically invalidate a paper.

Across 5,819 source documents, we found six retraction notices and 22 correction notices. Exact notice links created 129 review holds.

All six explicit retraction targets were outside this acquired pool. That does not prove every acquired paper is free from retraction.

The overlap checks found no matches under the frozen exact/text criteria across the main acquired pools. They do not cover every possible benchmark or semantic duplicate.

Problem C: the article classifier confused background with the main study question

We first screened titles and abstracts. A paper could discuss cardiovascular risk in its background without studying a cardiac outcome.

We added source evidence and exact quotations. An intermediate change rejected every reviewed positive. That failure showed a problem with definitions and prompt visibility.

We made the output schema and study definitions explicit. The repaired 29-case development screen passed quote/design checks for 28 cases. One remained unresolved.

A fresh 20-case check still found an incorrect clear inclusion and ambiguous scope cases. These labels came from agent review, not expert adjudication.

We therefore kept the classifier as a triage aid. It does not admit articles automatically.

5. Project 2: repair agent plus experiment agent

What does an agent add?

An agent uses a model to choose actions, such as reading a file, editing code, or running a test. A controller limits those actions.

You chose two connected missions: repository repair and an ML experiment copilot patterned on Karpathy's autoresearch.

Retrieval means selecting relevant stored information. Here, it supplies repository hints or previous experiment records. This is different from biomedical article QA.

6. Project 3: ECG classification that survives harder tests

Is this vision deep learning?

This is deep learning for one-dimensional physiological signals. A 1D CNN slides filters along a waveform. It does not classify ordinary images.

Some methods resemble computer vision methods, such as convolution and attention. The current project is best described as ECG time-series deep learning.

The model classifies beats around known reference R peaks. It is not a tested beat detector, live monitor, or clinical decision system.

Four classes used in the new primary experiments

LabelMeaning
NNormal-category beats
SSupraventricular ectopic beats
VVentricular ectopic beats
FFusion of normal and ventricular beats

Precision asks how many predicted class members were correct. Recall asks how many true class members were found.

Macro F1 averages each class's F1 equally. It helps expose weak rare classes hidden by overall accuracy.

Problem A: the old high score did not establish performance on new people

We downloaded raw MIT-BIH signals and annotations, verified files, and retained record identity. The source has 48 recordings from 47 subject groups.

We used a primary four-class scope and split subject groups before fitting preprocessing. The first baseline tested 17,043 beats from seven unseen groups.

It achieved 94.10% accuracy but only 0.4521 macro F1. It found one of 429 S beats and none of 384 F beats.

Why accuracy was misleading:

15,101 of the 17,043 test beats were N. A model could look strong overall while missing nearly all S and F beats.

Problem B: weighting helped, but past context did not solve the rare classes

We compared three arms on the same eligible targets: unweighted single beat, weighted single beat, and weighted target plus two prior beats.

Class weighting makes mistakes on rare training classes more costly. Past context adds neighboring waveforms and RR intervals, the times between beats.

Macro F1 was 0.378, 0.555, and 0.510 respectively. Weighting helped more than this particular context design.

The weighted arm still found no F beats. The context arm found six of 384. Most S and F test beats belonged to two influential people.

Validation had only 15 F beats. Many beats from one person do not replace many independent people.

The windows include signal after each R peak. Some prior windows overlap the target time. A strictly causal streaming method needs a different input contract.

Problem C: transfer to another dataset failed

We prepared INCART: 175,777 eligible beats from 75 records and 32 patients. We fixed lead choice, labels, resampling, and preprocessing before its first score.

The MIT-trained weighted model reached only 0.233 macro F1 and 47.0% accuracy. It found none of the 219 F beats.

Domain shift means the input distribution changes between sources. Here, amplitudes, lead configuration, sampling, patients, and annotations differed.

A raw-signal check reproduced large INCART variation before resampling. We did not find evidence of a simple unit-conversion error.

Change: compare baseline handling and waveform scaling

Per-window centering subtracts a window's baseline level. A second variant also used robust scaling.

Personal extension: decline unfamiliar or uncertain beats

Abstention means the model declines to classify some inputs. Coverage is the fraction it accepts.

We compared confidence alone with confidence plus distance from training features. The added distance represented unfamiliarity.

The new rule reduced some accepted-beat error rates. It also rejected many rare beats, so a lower error could hide lost coverage.

At the 50% validation cutoff, INCART error fell from 11.91% to 4.85%. Actual coverage fell from 35.3% to 25.8%.

F retention fell from 28.8% to 3.7%. The rule rejected 211 of 219 F beats. This is not a minority-sensitive success.

Class retention is different from recall. Keeping a true F beat does not mean the classifier labels it correctly.

8. What should happen next, and how?

Start with the unresolved evidence and data decisions. Then run small matched comparisons. Increase scale after those comparisons justify it.

This is a proposed sequence, not a newly approved experiment budget. Wayfinder planning can follow our discussion, as you requested earlier.

Project 1: make the article task trustworthy before training

  1. Retrieve and inspect the 32 raw outputs. Verify case and source coverage. Count fences, malformed structures, truncated answers, and quote failures separately.
  2. Define a transparent format repair. If a complete fenced JSON object exists, test a narrowly defined wrapper-removal parser on saved outputs. Preserve the original strict failures and label derived results separately.
  3. Evaluate scientific decisions. Compare validated labels with the frozen draft review. Inspect background-versus-core mistakes and mixed study designs. Preserve uncertain cases.
  4. Decide corpus policy. Define which human studies, reviews, cases, and preclinical articles belong in which tier. Resolve notice holds, license records, text completeness, and evaluation exclusions.
  5. Build source-disjoint QA data. Keep training articles separate from development and final questions. Record exact evidence, acceptable answers, and unsupported questions. Separate versions of the same article.
  6. Run a bounded training pilot. Compare the unchanged base model with a small adaptation. Then compare continued pretraining, response-only SFT, or their combination under a frozen design.
  7. Expand only after answer quality improves. Measure answer accuracy, support, abstention, formatting, language-model loss, runtime, and memory. A lower text loss alone is insufficient.

Completion criterion: a reproducible model comparison that improves supported answers on unseen articles without increasing unsupported claims.

Project 2: test whether memory actually helps

  1. Keep runtime-aware feedback. Give both arms the same metric direction, incumbent, allowed edits, and validity checks.
  2. Freeze a new matched comparison. Change only access to history. Use several predefined seeds, the same starting model, evaluator, hardware, and time allowance.
  3. Define interrupted-run handling before launch. Separate preemption from bad proposals. Specify a finite recovery allowance and output policy.
  4. Measure both quality and cost. Report improvements over the incumbent, valid proposal rate, repeated proposals, tool or model tokens, and GPU time. Report every attempt.
  5. Broaden repair tasks separately. Use independent repositories and unseen bugs. Limit broad file reading and require focused inspection. Verify target and regression tests outside the model.
  6. Freeze a later final task set. Keep it outside the memory index until the controller and policy are fixed.

Completion criterion: repeatable evidence that history improves the useful outcomes or efficiency of the same bounded agent.

Project 3: improve rare-class evidence and cross-source design

  1. Check source overlap and grouping. Compare recording segments and metadata across releases. State any patient-identity uncertainty explicitly.
  2. Choose a lead-aware mission. Decide whether V5 is a separate transport test or part of a multi-lead/source training design. Avoid mixing channels silently.
  3. Improve independent S/F coverage. Inspect which people contribute rare classes. A larger N-heavy dataset alone will not solve rare-class scarcity.
  4. Freeze a compact model comparison. Keep the centered CNN control. Test one justified change, such as rhythm representation or loss design, across several seeds.
  5. Set minority-sensitive reliability goals. Evaluate precision, recall, patient spread, calibration, and coverage. Any abstention rule needs explicit S/F retention requirements.
  6. Use the sealed confirmation source once. After the model, preprocessing, and abstention policy are frozen, evaluate the reserved source without tuning on it.
  7. Build a demo after the model contract is clear. Show accepted, declined, and uncertain results. Add causal beat detection only as a separate validated task.

Completion criterion: stable performance across people, useful rare-class precision and recall, and transparent limits on a fresh source.

Before each new batch:

Write the question, data size, split, control, allowed changes, seeds, success metric, runtime cap, and stopping rule. Then execute and preserve every outcome.

10. Small glossary

Token
A text unit used by a language model. A tokenizer may split a word into several tokens.
XML / JATS
A structured article format. It separates fields such as title, abstract, body sections, and references.
R peak
A prominent waveform point used here as the known center of a heartbeat window.
Cross entropy
A loss that measures how much probability the model gives the correct outcome. Lower is better.
F1
A score that combines precision and recall. Macro F1 averages the class scores equally.
Continued pretraining
Train an existing language model to predict text from a new domain.
SFT
Supervised fine-tuning: train on input-and-answer examples. Response-only loss trains on the answer tokens.
QLoRA
Train small adapter weights while the base model stays quantized and mostly frozen.
RAG
Retrieve relevant documents or passages and supply them to a model. Retrieval and answer support need separate evaluation.
Seed
A value that controls random initialization or sampling. Several seeds reveal variation.
Incumbent
The current reference candidate that a proposed change must beat.
Validation
Data used to choose settings or checkpoints. Repeated use can adapt the system to this data.
Development test
A previously inspected test now used to guide improvements. It is no longer untouched confirmation.
Calibration
How well predicted confidence matches observed correctness.
Slurm
The cluster scheduler that allocates CPUs, memory, GPUs, and job time.
Preemption
The scheduler interrupts a job to reclaim its resources.
Evidence gate
A check that must pass before accepting a result. Passing a file-format check does not prove scientific truth.
